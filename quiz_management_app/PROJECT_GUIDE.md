# Project Guide

## What This Program Does

This is a small multiple-choice quiz that runs in the terminal. The player enters a name, chooses a category, answers each question using an option number, and sees a score. Questions are stored in SQLite. Every completed quiz appends one line to `file.txt`.

The terminal version does not ask players to log in, and it does not use the old browser interface.

## Technologies

- **Python 3.8+** runs the program and contains the quiz logic.
- **Python standard library** supplies the terminal input/output, dates, file handling, SQLite support, and JSON conversion. No external Python package is required.
- **SQLite** stores question categories, question text, options, and the correct option index in `data/quiz.db`.
- **JSON serialization** is used inside SQLite to store each question's list of options. This is not the same as loading the old `.json` files in `data/`.
- **Plain text** is used for quiz history in `file.txt`.

## Files Used By The Terminal Quiz

### `main.py`

This is the program's entry point. Run it with `python main.py`.

It initializes the database, gets the available categories, prompts for a player name and category, asks the questions, checks each answer, calculates the percentage, and appends a timestamped result line to `file.txt`. If the player submits an invalid number, it asks again. If no categories exist, it prints instructions for loading sample questions.

### `backend/database.py`

This module connects the Python program to `data/quiz.db`. It creates the `data/` folder if needed, creates database tables when the program starts, and provides helper functions for reading and writing database rows.

The terminal quiz uses these question-related functions:

- `init_db()` creates the database tables if they do not exist.
- `get_categories()` returns the available categories.
- `load_questions(category)` returns that category's questions and converts the saved options JSON back into a Python list.

The file also contains user and database-results helpers left over from the former web version. The terminal `main.py` does not currently use those helpers. The terminal quiz saves its attempt in `file.txt`, not the SQLite `results` table.

### `backend/__init__.py`

Marks `backend` as a Python package so `main.py` and the seeding script can import `backend.database`.

### `scripts/seed_questions.py`

Contains eight sample multiple-choice questions and inserts them into SQLite. Run it with `python -m scripts.seed_questions`. Running it more than once adds another copy of the sample questions; it does not replace or deduplicate existing questions.

### `data/quiz.db`

The active SQLite database. The question table contains fields for an ID, category, difficulty, question text, answer options, and the correct answer index. The database setup also creates `users` and `results` tables for the former web app, but those tables are not part of the current terminal quiz flow.

### `file.txt`

The terminal quiz creates this file after the first completed attempt. It appends one UTF-8 text line per quiz rather than replacing the previous results. A line contains the date and time, player name, category, correct score, total questions, and percentage. Example:

```text
2026-09-28T09:07:08 | anvesh | General Knowledge | 3/3 (100%)
```

## Files And Folders Not Used By The Current Quiz

- `data/questions.json`, `data/users.json`, and `data/results.json` are old JSON data files. The active program does not read or update them; questions come from `data/quiz.db` and completed terminal scores go to `file.txt`.
- `frontend/` currently contains only empty `css/` and `js/` folders. There is no active browser UI.
- `quiz_app/` currently contains only Python cache files from the previous implementation. It has no active source code and is not imported by `main.py`.
- `__pycache__/` directories and `.pyc` files are generated by Python when code is imported. They are not source code and can be regenerated.
- `.venv/` is the project's Python virtual environment. It holds a Python environment for this workspace; the app itself has no third-party package dependency.

## Run It

Open a terminal in the project folder and run:

```powershell
python main.py
```

If Python is not available from `PATH`, use the project's virtual environment:

```powershell
.\.venv\Scripts\python.exe main.py
```

Enter a name, select the displayed category number, then answer with the number beside each option. When the quiz ends, the score is displayed and appended to `file.txt`.

If there are no questions in the database, add the sample questions first:

```powershell
python -m scripts.seed_questions
```

## Program Flow

```text
main.py
  -> backend.database.init_db()
  -> read categories from data/quiz.db
  -> ask player name and category
  -> load questions for the selected category
  -> show options and check answers
  -> calculate score and percentage
  -> append result to file.txt
```
